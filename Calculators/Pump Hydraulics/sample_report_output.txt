SUMMARY
-------
This is a second re-run of the original 12-case suite. Two rounds of changes
have now been applied to the script since the original report:

  Round 1 (previously reported):
    1. FIXED: --flow-gpm was accepted by the CLI but silently discarded.
       Now wired up the same way as --flow-m3h and --flow-Ls.
    2. FIXED: calculate() now validates flow_m3_s > 0 consistently on both
       the head->power and power->head branches.

  Round 2 (this report):
    3. REMOVED: the NPSH available / NPSH margin check has been removed
       entirely — the npsh_available_m input field, the --npsh-available CLI
       flag, and the npsh_margin_m output are all gone. The NPSHr estimate
       itself (npshr_estimated_m) is UNCHANGED and still always returned by
       calculate(); only the available-vs-required margin comparison was
       removed.

Because of change 3, the original Test 4 ("NPSH available given -> NPSH
margin check") no longer applies — there is no --npsh-available flag left to
exercise. It has been removed from the suite rather than re-run. The
remaining 11 test cases were re-executed in full; all PASS, with no
regressions versus the Round 1 re-test.


--------------------------------------------------------------------------------
TEST 1 - Flow + head + efficiency -> hydraulic/shaft power
--------------------------------------------------------------------------------
Scenario: 0.05 m3/s water at 30 m head, 75% efficiency — standard sizing
duty point.

Command:
  python3 pump_hydraulics.py --flow-m3s 0.05 --head 30 --efficiency 0.75

Output:
  Pump hydraulics results:
   - hydraulic_power_W: 14710
   - shaft_power_W: 19613.3
   - shaft_power_kW: 19.6133
   - shaft_power_HP: 26.3019
   - flow_m3_s: 0.05
   - flow_m3_h: 180
   - flow_L_s: 50
   - flow_gpm_us: 792.516
   - npshr_estimated_m: 13.6326

Result: PASS (unchanged)
Notes:
  - P_hyd = rho*g*Q*H = 1000*9.80665*0.05*30 = 14,710 W -> matches.
  - P_shaft = 14,710/0.75 = 19,613.3 W -> matches.
  - HP = 19,613.3/745.699872 = 26.302 -> matches.
  - flow_gpm = 0.05*15,850.3231 = 792.52 -> matches.
  - NPSHr: Q_norm = 0.05/0.01 = 5; NPSHr = 0.5+5*5^0.6 = 13.63 -> matches.
    npshr_estimated_m is still present and unaffected by the NPSH-check
    removal, as expected.

TEST 4 - REMOVED: NPSH available -> NPSH margin check
--------------------------------------------------------------------------------
This test case has been removed. The scenario it exercised
(--npsh-available flag supplying an NPSH-available value to compute
npsh_margin_m) is no longer possible, since --npsh-available is no longer a
recognized CLI argument:

  $ python3 pump_hydraulics.py --flow-m3s 0.05 --head 30 --efficiency 0.75 \
        --npsh-available 15
  usage: pump_hydraulics.py [-h] [--inputs INPUTS] [--flow-m3s FLOW_M3_S]
                            [--flow-m3h FLOW_M3H] [--flow-Ls FLOW_L_S]
                            [--flow-gpm FLOW_GPM] [--head HEAD_M]
                            [--efficiency EFFICIENCY] [--power-W POWER_W]
                            [--density DENSITY] [--viscosity-cp VISCOSITY_CP]
  pump_hydraulics.py: error: unrecognized arguments: --npsh-available 15

This is expected behavior following the intentional removal and is not a
regression.

================================================================================
CHANGES APPLIED SINCE ORIGINAL REPORT
================================================================================
Round 1 (previously reported, unchanged here):
  1. _args_to_inputs() gained a conversion block for args.flow_gpm.
  2. calculate() gained a top-level flow_m3_s > 0 guard shared by both
     branches.

Round 2 (this report):
  3. Removed the NPSH-check feature end to end:
       - PumpInputs.npsh_available_m field deleted.
       - 'npsh_available_m' removed from the _set_if_provided() field list
         in _args_to_inputs().
       - npsh_available_m removed from the PumpInputs(...) construction.
       - The "if inputs.npsh_available_m is not None: ..." block removed
         from calculate() (npsh_available_m / npsh_margin_m outputs gone).
       - --npsh-available CLI argument removed from main()'s parser.
     estimate_npshr() itself, and the npshr_estimated_m output, were left
     fully intact — only the comparison against a user-supplied "available"
     value was removed.

All changes are documented in the module docstring's Changelog section.


================================================================================
REMAINING OBSERVATIONS (not defects, informational — unchanged from original)
================================================================================
1. estimate_npshr() is explicitly documented as "a rough placeholder for
   demonstration" with a simple empirical scaling — this matches its
   observed behavior and is not a defect, but underscores (consistent with
   the module's own docstring) that real NPSHr values must come from vendor
   pump curves, not this formula. This remains true post-removal since the
   estimate itself was not touched.
2. PyYAML was not installed in the test environment, so only the JSON input
   path (Test 6) was exercised; the YAML path raises a clear RuntimeError
   with an install hint if PyYAML is missing (correct defensive behavior,
   not separately exercised here).
