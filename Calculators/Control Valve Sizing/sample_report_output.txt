SUMMARY
-------
9 test cases executed: 5 successful sizing runs (metric flow+dP -> Kv/Cv, Kv ->
flow, Cv -> flow with specific gravity, JSON file input, imperial-only input)
plus 4 error/validation cases. All numeric results were independently
hand-verified against the module's own Kv/Cv/unit-conversion formulas (see
Verification Notes below) and matched exactly. One real inconsistency was
found in input validation: pressure-drop checks exist on the "compute Kv/Cv
from flow" side but are missing on the "compute flow from Kv/Cv" side,
producing a confusing raw Python error instead of a clean message in two of
the four sizing paths (see Observation 1 / Tests 8-9).

TEST 1 - Flow + deltaP (bar) -> Kv/Cv (metric input)
--------------------------------------------------------------------------------
Scenario: 50 m3/h liquid flow across a 0.2 bar pressure drop; the most common
sizing direction (given a duty, find the required Kv/Cv).

Command:
  python3 control_valve_sizing.py --flow-m3h 50 --deltaP-bar 0.2

Output:
  Control valve sizing results:
   - kv_m3h_per_sqrt_bar: 111.803
   - cv_usgpm_per_sqrt_psi: 129.245

   - flow_gpm_us: 220.143
   - deltaP_bar: 0.2
   - deltaP_psi: 2.90075

Result: PASS
Notes:
  - Kv = Q/sqrt(dP) = 50/sqrt(0.2) = 111.803 -> matches.
  - Cv = 1.156*Kv = 129.24 -> matches.
  - deltaP_psi = 0.2*14.5037738 = 2.90075 -> matches.
  - flow_gpm = 50*4.4028675 = 220.143 -> matches.

--------------------------------------------------------------------------------
TEST 7 - Error handling: deltaP-bar = 0 on the flow->Kv path
--------------------------------------------------------------------------------
Scenario: Zero pressure drop supplied alongside a flow value.

Command:
  python3 control_valve_sizing.py --flow-m3h 50 --deltaP-bar 0

Output (stderr):
  Error: deltaP must be > 0 bar

Exit code: 2

Result: PASS
Notes:
  - kv_from_flow_and_dP() explicitly checks deltaP_bar <= 0 and raises a
    clear, specific error. This is the "good" validation behavior that
    Tests 8-9 below show is missing on the reverse (Kv/Cv -> flow) paths.


--------------------------------------------------------------------------------
TEST 8 - Error handling GAP: negative deltaP-psi on the Cv->flow path
--------------------------------------------------------------------------------
Scenario: Cv given with a negative pressure drop, which is physically invalid.

Command:
  python3 control_valve_sizing.py --cv 25 --deltaP-psi -5

Output (stderr):
  Error: math domain error

Exit code: 2

Result: FAIL (validation gap - see Observation 1)
Notes:
  - flow_from_cv() computes cv*sqrt(deltaP_psi/sg) with NO check that
    deltaP_psi > 0, unlike cv_from_flow_and_dP_gpm_psi() which does check.
  - A negative deltaP_psi produces sqrt() of a negative number, raising a
    raw Python "math domain error" ValueError instead of a clear message
    like "deltaP must be > 0 psi". The script still exits cleanly (code 2,
    caught by the generic except in main()), but the message is not
    actionable for an end user.


--------------------------------------------------------------------------------
TEST 9 - Error handling GAP: negative deltaP-bar on the Kv->flow path
--------------------------------------------------------------------------------
Scenario: Same class of issue as Test 8, but on the Kv+deltaP_bar path, to
confirm the gap is systemic rather than a one-off.

Command:
  python3 control_valve_sizing.py --kv 40 --deltaP-bar -0.5

Output (stderr):
  Error: math domain error

Exit code: 2

Result: FAIL (validation gap - see Observation 1)
Notes:
  - flow_from_kv() likewise has no deltaP_bar > 0 check before calling
    math.sqrt(). Confirms the same validation gap exists on both the
    Kv->flow and Cv->flow branches, while both "compute Kv/Cv from
    flow+dP" functions (Test 1/Test 7 path) do validate correctly.

================================================================================
OBSERVATIONS / RECOMMENDATIONS
================================================================================
1. VALIDATION GAP (Tests 8-9, real inconsistency, recommend fixing):
   kv_from_flow_and_dP() and cv_from_flow_and_dP_gpm_psi() both correctly
   raise a clear ValueError ("deltaP must be > 0 bar/psi") for non-positive
   pressure drops. However, flow_from_kv() and flow_from_cv() — used on the
   reverse "given Kv/Cv, find flow" paths — perform no such check and let a
   non-positive deltaP flow straight into math.sqrt(), producing an opaque
   "math domain error" instead. Recommend adding the same
   "if deltaP <= 0: raise ValueError(...)" guard to both functions for
   consistent, user-friendly error messages across all input paths.
2. The module explicitly scopes itself to liquid (incompressible) sizing
   only, with gas/compressible sizing "intentionally left out as a
   placeholder" per its own docstring — this is accurate and no gas-related
   functionality was found or tested.
3. specific_gravity defaults to 1.0 and is silently ignored on the metric
   (Kv, bar) paths — this matches the documented Kv definition (which has
   no explicit SG term) and is consistent with standard Kv usage, so not a
   defect, just worth noting if a user expects SG to apply uniformly across
   both unit systems.
4. PyYAML was not installed in the test environment, so only the JSON input
   path (Test 4) was exercised; the YAML path raises a clear RuntimeError
   with an install hint if PyYAML is missing (correct defensive behavior,
   not separately exercised here).
