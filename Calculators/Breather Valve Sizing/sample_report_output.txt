BREATHER VALVE SIZING UTILITY - SAMPLE TEST REPORT
Script under test: breather_valve.py
Test date: 2026-08-09
Python: 3.12.3

SUMMARY
-------
This module has no CLI/argparse interface (unlike the other scripts in this
series) — it's a small function library plus a __main__ demonstration block.
Testing was done by running the built-in demo and by importing the three
public functions directly in a standalone test script. 16 test cases
executed: 4 successful sizing calculations (the built-in demo's 2 examples
plus 2 additional liquid/gas cases with different fluids and gas properties)
plus 12 error/edge cases. All numeric results were independently hand-
verified against the module's own orifice/choked-flow formulas AND
cross-checked against the already-verified psv_sizing.py choked-flow
implementation using identical inputs — both scripts agreed to floating-point
precision (relative difference ~1e-16), giving strong confidence in the core
physics. Two real, related gaps were found in area_for_choked_gas_mass_flow():
it validates m_dot, P0, and T0, but NOT gamma (gamma=1.0 crashes with a raw
ZeroDivisionError), M_kg_per_mol (M=0 also crashes), or Cd (a negative Cd is
silently accepted and returns a physically meaningless negative area) — all
three are validated correctly in the sibling orifice_area_liquid() function,
but the equivalent checks were not carried over to the gas function.


--------------------------------------------------------------------------------
TEST 1 - Built-in demo block (both examples)
--------------------------------------------------------------------------------
Command:
  python3 breather_valve.py

Output:
  Breather valve sizing examples:

  Liquid example: Q=0.01 m3/s, rho=1000.0 kg/m3, deltaP=1000.0 Pa, Cd=0.62
    -> area = 1.140495e-02 m^2 (dia = 120.50 mm)

  Gas (choked) example: m_dot=0.5 kg/s, P0=500000.0 Pa, T0=293.0 K, Cd=0.8
    -> area = 5.293786e-04 m^2 (dia = 25.96 mm)

Result: PASS
Notes:
  - Liquid: denom = 0.62*sqrt(2*1000/1000) = 0.8768; A = 0.01/0.8768 =
    0.011405 m2 -> matches. diam = sqrt(4A/pi)*1000 = 120.50 mm -> matches.
  - Gas: R_specific = 8.314462618/0.02897 = 286.98 J/(kg.K);
    K = (2/2.4)^3 = 0.5787; A = m_dot*sqrt(R_spec*T0) /
    (Cd*P0*sqrt(gamma)*K) = 144.99/273,864 = 5.2938e-4 m2 -> matches.

--------------------------------------------------------------------------------
TEST 14 - BUG: gamma = 1.0 on the gas function crashes with a raw
ZeroDivisionError
--------------------------------------------------------------------------------
Scenario: gamma=1.0 (an unphysical but not-inherently-rejected input, e.g. a
data-entry slip) makes the K exponent's denominator, 2*(gamma-1), equal to
zero.

Call:
  area_for_choked_gas_mass_flow(0.5, 5e5, 293, gamma=1.0)

Output:
  ZeroDivisionError: float division by zero (unhandled)

Result: FAIL - real gap (see Observation 1)
Notes:
  - area_for_choked_gas_mass_flow() validates m_dot, P0, and T0 but has no
    check that gamma > 1 (gamma must be strictly greater than 1 for the
    ideal-gas isentropic/choked-flow formulas to be defined at all — this
    mirrors psv_sizing.py's critical_pressure_ratio(), which has the same
    mathematical requirement but likewise doesn't validate it explicitly).
    The failure surfaces as a raw ZeroDivisionError rather than a clear
    "gamma must be > 1" message.


--------------------------------------------------------------------------------
TEST 15 - BUG: M_kg_per_mol = 0 crashes with a raw ZeroDivisionError
--------------------------------------------------------------------------------
Call:
  area_for_choked_gas_mass_flow(0.5, 5e5, 293, M_kg_per_mol=0)

Output:
  ZeroDivisionError: float division by zero (unhandled)

Result: FAIL - real gap (see Observation 1)
Notes:
  - R_specific = R_UNIVERSAL / M_kg_per_mol divides by the molar mass with
    no check that it's > 0, unlike every other physically-required-positive
    parameter in this module (Q, rho, deltaP, P0, T0 are all validated).


--------------------------------------------------------------------------------
TEST 16 - BUG: negative Cd on the gas function is silently accepted and
returns a NEGATIVE (physically meaningless) area
--------------------------------------------------------------------------------
Call:
  area_for_choked_gas_mass_flow(0.5, 5e5, 293, Cd=-0.8)

Output:
  No error raised. area = -0.0005293786089498707 m2

Result: FAIL - real gap (see Observation 1)
Notes:
  - orifice_area_liquid() explicitly validates
    "if not (0 < Cd <= 1.5): raise ValueError(...)" for the liquid case, but
    area_for_choked_gas_mass_flow() has NO equivalent Cd check at all. A
    negative (or absurdly large) Cd passes straight through and, because Cd
    appears only in the denominator (not squared), the sign carries directly
    into the result — silently producing a negative orifice area with no
    error. This is the same class of issue as the liquid function already
    guards against, just not carried over to the gas function.


================================================================================
CROSS-VALIDATION AGAINST psv_sizing.py (independent formula check)
================================================================================
Since breather_valve.py's choked-flow formula and psv_sizing.py's choked-
flow formula (independently reviewed and hand-verified in an earlier report
in this series) both implement the same underlying physics via different
code, they were run side-by-side on identical inputs as an extra layer of
verification beyond manual arithmetic:

  Inputs: m_dot=1.0 kg/s, P0=3e5 Pa, T0=300 K, M=0.02897 kg/mol (28.97
          g/mol), gamma=1.4, Cd=0.8 (P2 set deep enough to guarantee choked
          flow in psv_sizing.py's more general solver)

  breather_valve.py  area_for_choked_gas_mass_flow() -> 0.0017855497319970081 m2
  psv_sizing.py      required_area_for_gas_massflow() -> 0.0017855497319970084 m2
                      (confirmed choked: True)

  Relative difference: 1.21e-16 (floating-point noise only)

This is strong independent confirmation that both scripts' choked ideal-gas
flow implementations are mathematically equivalent and correct.

================================================================================
OBSERVATIONS / RECOMMENDATIONS
================================================================================
1. GAP (Tests 14-16, recommend fixing): area_for_choked_gas_mass_flow()'s
   input validation is noticeably less complete than orifice_area_liquid()'s
   in the same file:
     - No check that gamma > 1 (required for the isentropic/choked formulas
       to be mathematically defined at all) -> gamma=1.0 raises a raw
       ZeroDivisionError.
     - No check that M_kg_per_mol > 0 -> M=0 raises a raw ZeroDivisionError.
     - No check on Cd's range at all (orifice_area_liquid enforces
       0 < Cd <= 1.5) -> a negative Cd is silently accepted and produces a
       NEGATIVE area with no error, which is the most concerning of the
       three since it doesn't crash — it just returns a wrong-looking-but-
       plausible-shaped number.
   Recommend adding the same style of upfront validation used in
   orifice_area_liquid(): "if gamma <= 1: raise ValueError(...)",
   "if M_kg_per_mol <= 0: raise ValueError(...)", and a Cd range check
   consistent with the liquid function's "0 < Cd <= 1.5" convention (or a
   gas-appropriate equivalent, since typical gas Cd values reach ~0.95 per
   the function's own docstring).
2. This module has no CLI or file-input support (JSON/YAML/argparse) unlike
   every other script tested in this series — it's purely a function
   library plus a demo block. This is a design choice, not a defect; it
   just means testing here was done via direct Python calls rather than
   command-line invocation.
3. The choked-flow formula was independently cross-validated against
   psv_sizing.py's already-verified implementation and matched to floating-
   point precision, which is strong evidence the core gas-sizing physics is
   correct — the issues found here are entirely about missing input
   validation, not incorrect formulas.
4. As with the other scripts in this series, the module correctly documents
   its own scope and limitations (choked-flow-only for gas, incompressible-
   only for liquid) in its docstrings, consistent with what was observed in
   testing.
